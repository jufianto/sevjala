Hard-to-reverse choices beyond the blueprint get an [ADR](./adr/README.md).

| D-011 | 2026-10-12 | The pairing code lives only in the node agent's memory (no keyring in M1); an agent restart clears it. | Never on disk; the keyring arrives with the DB password in M2. Restart mid-pairing costs one `sevjala code`. |
| D-012 | 2026-10-12 | While a code is active a node accepts any client cert, for `/identity` and `/pair` only; a successful pair replaces the trusted controller. | D-013 | 2026-10-12 | LAN `GET /status` in M1 returns `agent_id, role, version, uptime_s, health, backups:[], problems:[]`; `store` arrives in M2. Local `/status` adds `agent_id`, `fp`. | Only what M1 can fill truthfully. |
| D-014 | 2026-10-12 | CLI `<agent>` = exact agent_id, else hostname (any case), else a unique agent_id prefix of at least 4 chars; ambiguity lists the candidates. | Nobody types a UUID; never guess between two PCs. |
| D-015 | 2026-10-12 | Discovery results are cached in controller memory; `pair` needs a `discover` or `agents add` in the same agent run. Discover refreshes hostname/address of a paired agent whose fp matches. | Pairing must pin the fp seen before the code is sent; DHCP changes heal on the next discover. |
| D-016 | 2026-10-12 | Role logic lives in package `coord` behind `localapi.Backend` (not in the blueprint's package list). | Keeps `localapi` free of LAN code and the role switch in one place. |
| D-017 | 2026-10-12 | Windows firewall rules `Sevjala-LAN-API` (TCP) and `Sevjala-Discovery` (UDP): port-scoped, inbound allow, all profiles; install recreates them, uninstall removes them. | Rule names without spaces survive `netsh` quoting; port scope survives moving the binary. |
| D-018 | 2026-10-13 | `sevjala code` shows the node's first 16 fingerprint hex chars; `pair` requires `--fp` and checks it against the discovered fingerprint before any network call (409 "do not pair", the code is not consumed). | Closes I-5: a LAN device answering discovery could capture the HMAC proof and brute-force the 6-digit code offline. 64 bits is out of reach for certificate grinding. |
| D-019 | 2026-10-13 | Detection (and M4 restore) uses the `mysql`/`mariadb` client binary next to the dumper; no Go MySQL driver. | Keeps the blueprint's dependency list; the client ships with every XAMPP. |
| D-020 | 2026-10-13 | The DB password lives in the OS keyring (service `sevjala`, account `db`), written by the agent (SYSTEM/root) through `db set`. Linux without a Secret Service uses AES-256-GCM `secrets/db.enc` keyed by `secrets/key` (0600) and logs `keyring_fallback`. Child processes get it only via `MYSQL_PWD`; an inherited `MYSQL_PWD` is dropped; client stderr is scrubbed of it. | Blueprint: secrets in the keyring. The CLI user's keyring is not the service's. `MYSQL_PWD` keeps it off argv and disk. |
| D-021 | 2026-10-13 | Dumps add `--default-character-set=utf8mb4` to the blueprint's flags. | The 10.4 client defaults to latin1 and mangles or rejects 4-byte characters (seen in the integration test). |
| D-022 | 2026-10-13 | New dependencies: `github.com/zalando/go-keyring` (blueprint-named) and `golang.org/x/term` (no-echo password prompt). | `x/term` is the standard no-echo prompt and depends only on `x/sys`; both build with go-win7. |
| D-023 | 2026-10-13 | Node store default `<data-dir>/store` (inherits the locked ACL); `min_free_bytes` default 2 GiB; a PUT that would cross it is refused upfront with 507. `config.Write` writes every key, so a fresh install shows all defaults. | Backups stay admin-only by default; a full disk fails fast instead of mid-write. |
| D-024 | 2026-10-13 | Until M3 policies, every backup goes to every paired node; `backup now` without `--tag` tags it `manual`. | Owner choice; a manual backup must not look like a scheduled tier. |
| D-025 | 2026-10-13 | A dump in progress or failed exists only in controller memory (`dumping`/`failed`); the `backups` row is written after the rename and manifest (blueprint step 4). A controller start deletes `staging/*.part`. | No half-made rows; a restart forgets only what the log already recorded. |
| D-026 | 2026-10-13 | Transfer retries after 30 s, 2 min, 10 min; then `failed`, or `offline` when no attempt connected, until M3. 400/403/409 and a TLS rejection are not retried. A restart requeues `pending` and `transferring` copies. | Blueprint backoff without M3's status cycle; a node re-paired elsewhere should not burn twelve minutes. |
| D-027 | 2026-10-13 | `PUT /backups/{id}` uses `Expect: 100-continue`; an identical stored copy answers 200 without reading the body. The node allows 60 s between body reads; the controller cancels after 60 s without progress. | A lost 200 then costs no re-transfer; a hung peer frees its slot (verified with a frozen node in the Docker run). |
| D-028 | 2026-10-13 | `backup_copies.last_error` survives retries until the copy is verified; the backup state is recomputed on every copy change (`created` while any copy is pending/transferring, then `distributed` or `partial`). | The operator sees why a copy is retrying. |
| D-029 | 2026-10-13 | A node scan reports every corrupt case (size mismatch, manifest without file, file without manifest, unreadable manifest) as a problem without re-hashing; `health` is `warning` when there are problems; `.part` files are removed at agent start and when older than 1 h, and reported once by the next scan. | Transparent status without hashing gigabytes on every poll; hashes are checked again before restore (M4). |
| D-030 | 2026-10-13 | `doctor` gains a `WARN` level (shown, does not fail the run), used for "no database chosen yet" and store problems. | A fresh controller is not broken, only unfinished. |

## Open questions

From the blueprint (settle during P0/M1), plus gaps found while preparing the repo.

- [ ] Exact MariaDB/MySQL versions bundled with the XAMPP releases in use, to pin `mysqldump` flag compatibility
- [ ] Whether SERVER-01 has KB3125574, which decides go-win7 1.27 vs 1.26.x for the Win7 assets
- [ ] Staging `keep` default (12) vs available disk on the Controller
- [ ] Whether a node may serve two controllers in v2 (affects `peers.json` shape now)
- [x] **Before M2 (hard gate):** lock down the data dir (done in M1, D-010). On Windows `MkdirAll` under `%ProgramData%` inherits an ACL that lets Users create files, and a user can pre-create `C:\ProgramData\Sevjala\` with their own `config.toml`; once M2 makes SYSTEM run `controller.database.dumper`, that is a local privilege escalation. Install must set a protected DACL (SYSTEM + Administrators full, nothing for Users) owned by Administrators, refuse a pre-existing dir not owned by Administrators/SYSTEM, and on Unix require root ownership and no group/world write.
- [ ] M5: under UAC the tray runs un-elevated even for an admin user, so it cannot open a pipe ACL'd to Administrators + SYSTEM. Needs a read-only ACE for interactive users or a second pipe before M5.
- [ ] The blueprint cites a PRD ("design principle kept from the PRD", "every event in PRD section 25"). That PRD is not in the repo; the section 25 event list is needed before M1's definition of done can be met.
