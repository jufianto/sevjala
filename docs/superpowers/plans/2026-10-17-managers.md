# Managers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A paired backup PC marked as manager runs controller commands and the controller's dashboard over links the controller opens (AD-21).

**Architecture:** The controller keeps 4 mutual-TLS links per online manager, switched with `Upgrade: sevjala-manage`, and serves its local API handler on them as a non-admin caller labelled `<account> via <manager>`. The node pools those links and relays its local API's `/controller/…` through them; `--controller` and `sevjala ui --controller` use that relay.

**Tech Stack:** Go stdlib (`net/http` hijack, `crypto/tls`), cobra, modernc SQLite, Svelte 5.

**Spec:** `docs/superpowers/specs/2026-10-17-managers-design.md`

## Global Constraints

- Nodes never dial; the controller opens no new port or route; no firewall change.
- Pure Go, `CGO_ENABLED=0`, builds with go-win7; no new dependency.
- Admin only on the controller for marking a manager; admin-only actions from a manager answer 403 code `controller_admin_required`, message `<action> needs administrator rights on <controller hostname> itself`, and the CLI never elevates for it.
- Links: 4 per online manager, controller-side idle close 5 min, redial backoff 1 s doubling to 15 s, relay waits at most 20 s; `--controller` calls allow at least 30 s.
- `by` on link requests: `<X-Sevjala-By> via <manager hostname from the controller's store>`.
- Relay error texts exactly as the spec's table.
- Logs `slog` with `event`; new events `manager_set`, `manager_link_failed`.
- `docs/protocol.md` updated for `/manage`, the poll headers, the relay, `PUT /agents/{agent}/manager`, the status `controller` block and the new error code.

## Review Focus

1. The controller restarts or the link drops while a request is in flight (a long export). Expected: the relay answers 502 `{"error":"the link to <host> broke mid-way; try again"}` (or the CLI's stream error), never hangs; the next request uses a new link.
2. Manager turned off while a request is in flight. Expected: that request may finish; the links close after it; the next request gets the 403 "not a manager" from the relay within one poll.
3. Node restarts: pool empty, manager unknown. Expected: the relay waits (≤ 20 s), then 503 "has not contacted this PC since Sevjala started" if no poll came; after the next poll and links, it works without any user action.
4. A paired controller certificate calling `POST /manage` on a node whose latest poll said "not a manager", or any other certificate. Expected: 403, no link pooled (test in Task 4).
5. An active long stream (export of a 300 MB backup through the relay) lasting longer than the 5-minute idle close. Expected: idle close counts only idle time; the stream completes (test with a shortened idle in Task 5).

### Task 5: `manage` package — pool, relay, keeper

**Files:** Create `manage/pool.go`, `manage/relay.go`, `manage/keeper.go`, tests `manage/*_test.go`.

**Interfaces — Consumes:** Task 4 `Client.Manage`, `Server.Manager`; Task 2 `WithVia`.
**Produces:**
- `manage.Pool` (node): `NewPool() *Pool`; `Put(net.Conn)`; `Idle() int`; `Close()`; `Transport() *http.Transport` whose `DialContext` takes a pooled link, waiting until ctx ends.
- `manage.Relay(p *Pool, state func() RelayState, wait time.Duration) http.Handler` — serves `/controller/<route>`; `RelayState{Role, Paired, Known, Manager bool; Host, Self string; LastContact time.Time}`; error answers exactly as the spec's table; adds `X-Sevjala-By` from `logx.By(r.Context())`; streams bodies both ways; a link broken mid-request → 502 `the link to <host> broke mid-way; try again`.
- `manage.Keeper` (controller): `NewKeeper(dial func(ctx, agentID string) (net.Conn, error), serve http.Handler, log *slog.Logger, controllerHost string) *Keeper`; `Sync(ms []Manager)` with `Manager{AgentID, Hostname string}` starts/stops per-manager loops keeping `Links = 4`; `Close()`. Each link is served by an `http.Server` on a one-connection listener with `ConnContext` → `WithAdmin(false)`, `WithVia`, and a per-request middleware that sets `logx.WithBy(<X-Sevjala-By> + " via " + Hostname)` and re-checks `stillManager(agentID)` (403 + close if not). Idle close `IdleClose = 5 * time.Minute` (package var for tests); redial backoff 1 s → 15 s; `manager_link_failed` logged once per failure streak (`ErrOldNode` → reason "update Sevjala on <PC>").
