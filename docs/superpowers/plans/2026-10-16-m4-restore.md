# M4 Restore Implementation Plan

> Owner said "lets implement bro" before a full plan review: this is the short task list the
> session executes natively (TDD, one commit per task, master, no push). Spec:
> [2026-10-16-m4-restore-design.md](../specs/2026-10-16-m4-restore-design.md).

**Global constraints:** pure Go, `CGO_ENABLED=0`, go-win7 compatible; no new dependencies; the DB
password only via `MYSQL_PWD` (never args, logs, errors); operator text follows D-051 and says
"the controller's own copy", never "staging"; every new command has Long help and examples.

## Tasks

1. **dump restore primitives** — `dump/restore.go`: `ValidName(string) bool` (1–64 of
   `[A-Za-z0-9_$-]`), `DefaultTarget(db string, created time.Time) string`
   (`<db>_restored_<yyyymmdd_hhmm>`, local time, db part trimmed to fit 64), `Schema(ctx, Tools,
   Conn, db) (charset, collation string, exists bool, err error)`, `CreateDatabase(ctx, Tools, Conn,
   name, charset, collation string) error`, `DropDatabase(ctx, Tools, Conn, name string) error`,
   `TableCount(ctx, Tools, Conn, db string) (int, error)`, `Load(ctx, Tools, Conn, db string, gz
   io.Reader) error` (gunzip → `mysql --default-character-set=utf8mb4 <db>`). Fake client in
   `dumptest` learns these queries and a load mode (no `-e`, no `--routines`: reads stdin, logs
   `LOAD <db> <bytes>`; mode `LoadFails`). Integration test restores through `CreateDatabase` +
   `Load` and compares `CHECKSUM TABLE` per table (exit criterion).
2. **node serves backups** — `lanapi`: `GET /backups/{id}` (paired only) via
   `inventory.Store.Open`, headers as `PUT`; 404 / 409 / 400 per error. `Client.GetBackup(ctx,
   addr, nodeFP, id) (inventory.Manifest, io.ReadCloser, error)`: no overall timeout, stall
   watchdog, headers checked against the manifest. Tests: round trip, unpaired refused, missing 404,
   delete waits while streaming.
3. **controller restore into a new database** — `localapi` types `RestoreRequest`, `Restore`
   (+ state/step constants); `logx` events `restore_started`, `restore_source_failed`,
   `copy_corrupt`, `restore_succeeded`, `restore_failed`; `coord/restore.go`:
   `(*Controller).Restore(ctx, localapi.RestoreRequest) (localapi.Restore, error)`,
   `(*Controller).RestoreStatus(ctx) (localapi.Restore, error)`. Resolve id/`latest`, sources
   (own copy, then online nodes with a verified copy, newest `verified_at` first), fetch to
   `staging/<id>.restore.part` while hashing, mismatch → `MarkCopy(corrupt)` / own copy deleted
   and unstaged, next source; create target (source charset), load with progress, drop target on
   failure, table count. One restore at a time (409); the source backup counts as busy for
   retention. Tests on loopback with the fake client.
4. **replace production** — confirm must equal the database (409), refused while that database
   is dumping; source verified first; safety backup via `c.start([db], ["manual"])` and wait for
   `created`; mark the database replacing (`c.start` refuses it, so schedules skip with a log);
   drop, create with the old charset, load; failure message names
   `sevjala restore <safety id> --replace-production`.
5. **restore from a file** — `File` path: regular file + `<name>.json` manifest beside it,
   size/sha256 checked before load; nothing marked on mismatch.
6. **local API + service** — `POST /restore`, `GET /restore`; `Backend.Restore`,
   `Backend.RestoreStatus`; `coord.Service` role guard; `Client.Restore`, `Client.RestoreStatus`.
7. **CLI** — `sevjala restore <backup|latest> [--db] [--into | --replace-production]`,
   `--file PATH`; typed confirmation; watcher (step lines, % at most every 5 s, summary); Ctrl-C
   leaves it running; help group "Backups:".
8. **docs + smoke** — `protocol.md`, `decisions.md` D-056.., `smoke-tests.md` M4 (with timings),
   walkthrough step, README, PROGRESS; full verify; update the Windows controller and run a real
   restore + `CHECKSUM TABLE` comparison.
